# PLAY100 game design rules

PLAY100의 게임은 복잡한 기능 수보다 **제목, 소재, 환경, 조작, 피드백이 한 방향을 가리키는지**를 먼저 검토합니다.

## 1. One clear action

- 첫 조작은 설명 없이도 10초 안에 이해할 수 있어야 합니다.
- 모바일에서는 탭·드래그·한 버튼 중 하나를 중심으로 잡습니다.
- 규칙을 늘리기 전에 같은 조작에서 더 재미있는 상황을 만듭니다.

## 2. Title must become the world

- 제목에 항구가 있으면 배·부표·등대·암초·날씨가 실제 규칙과 피드백에 관여해야 합니다.
- 제목과 무관한 추상 버튼에 테마 이름만 붙이지 않습니다.
- 화면 장식, 목표, 실패 이유, 성공 연출이 같은 소재를 사용해야 합니다.

## 3. Short but replayable

- 첫 판 목표는 2~6분입니다.
- 재도전 이유는 무작위 대상, 더 좋은 점수, 메달, 다른 장면 중 최소 하나를 제공합니다.
- 실패 후 다시 시작하기까지 두 번 이상 누르게 하지 않습니다.

## 4. Feedback on every meaningful action

- 성공, 실수, 콤보, 위험, 완료를 시각·움직임·소리 중 두 가지 이상으로 전달합니다.
- 점수만 바뀌고 장면이 반응하지 않는 상태를 피합니다.
- 터치 화면에서도 피드백 위치가 손가락 주변에 보여야 합니다.

## 5. Environment changes before feature bloat

- 같은 규칙을 유지하더라도 시간대, 날씨, 공간 구조, 목표물 구성을 바꿔 새로운 상황을 만듭니다.
- 새로운 메뉴와 통화 체계보다 새로운 장면과 위험을 먼저 추가합니다.
- 외부 이미지가 없어도 SVG·Canvas·CSS로 소재가 읽히는 환경을 구성합니다.

## 6. Release gate

게임을 playable로 바꾸기 전에 다음을 확인합니다.

- 제목만 보고 예상한 소재가 첫 화면에 보이는가
- 10초 안에 첫 조작이 가능한가
- 모바일에서 주요 대상이 눌리는가
- 실패 이유를 장면만 보고 이해할 수 있는가
- 한 판 뒤 다시 해볼 이유가 있는가
- TypeScript, 검증 스크립트, production build가 통과하는가
